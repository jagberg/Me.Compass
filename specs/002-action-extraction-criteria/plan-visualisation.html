§ summary

The extraction step shared by email, chat, and meeting-notes sync has no defined criteria for what counts as an actionable item - the current prompt only says "actionable to-dos owed by the reader," never deliberately scoped. This plan rewrites that prompt's judgment rules. No new module, no schema change, no new dependency - the change lives entirely inside ClaudeCliService.extractActions().

§ 1How an item gets classified

ClaudeCliService.extractActions() - no new call, no new service.
Schematic - gates are criteria evaluated by one prompt, not separate pipeline steps.

§ 4Scope

In scope

  • Rewriting the extraction prompt's classification criteria
  • Scoping to items involving the user directly
  • Recall-first bias on ambiguous items
  • Keeping the existing local Claude CLI mechanism

Out of scope

  • Confidence scores, stored or displayed
  • A review / triage queue or any UI change
  • Source fetching, sync scheduling, or auth changes
